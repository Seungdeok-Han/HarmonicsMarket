# 발표 대본 (3~4분)

## 1) 시작 (20초)
- 안녕하세요. 악기 중고거래 플랫폼 v2 업그레이드 사례를 공유하겠습니다.
- 목표는 SNS·메시지·AI 기반 연습 추천과 진행도/일지를 추가하면서, 소프트웨어 공학 원리를 적용해 품질과 사용자 가치를 끌어올리는 것이었습니다.

## 2) 아키텍처 (40초)
- 클라이언트는 Jinja2 템플릿과 JavaScript(AJAX)로 구성했습니다.
- 서버는 Flask 기반으로 레이어드(MVC 개념) 설계를 적용했고, 도메인 모듈화와 Blueprint 분리를 지향합니다.
- 데이터는 SQLAlchemy + Alembic으로 모델/마이그레이션을 관리합니다.
- 외부 API는 Google Gemini로 개인화 연습 추천을, YouTube Data API로 영상 검색을 수행합니다.
- 인증/보안은 Flask-Login과 .env 환경변수로 관리합니다.

## 3) 유스케이스(30초)
- 현재 도메인은 거래, SNS/커뮤니티, 메시지, 연습(추천·진행도·일지), 인증입니다.
- v2에서 거래 중심에서 커뮤니티와 연습 관리까지 확장했습니다. (슬라이드: usecase_diagram)

## 4) 적용한 이론/패턴 (50초)
- 요구사항 공학으로 기능/비기능 요구를 명세하고 우선순위와 추적성을 확보했습니다.
- 아키텍처 원칙으로 Layered + MVC, 도메인 모듈화를 적용했습니다.
- 설계 패턴 사례:
  - State로 연습 곡/기술의 진행 상태를 일관되게 관리했습니다.
  - Strategy로 YouTube 한/영 폴백과 특정 곡 입력 시 프롬프트 분기를 구현했습니다.
  - Facade로 Gemini/YouTube API 호출을 캡슐화하여 라우트에서 분리했습니다.
  - Template로 base.html을 활용해 UI 일관성을 확보했습니다.

## 5) 효과: v1 → v2 (40초)
- 유지보수성: 모듈 경계로 변경 영향이 줄고 중복이 제거되었습니다.
- 확장성: 연습 추천 같은 신규 기능 추가 시 기존 코드 영향이 최소화되었습니다.
- 신뢰성: 요구 기반 검증과 회귀 체크리스트로 버그를 조기에 해결했습니다.
- 사용자 가치: 개인화 추천과 진행도/일지로 학습 동기를 강화했습니다.

## 6) 핵심 흐름 (30초)
- AI 연습 추천은 입력 → 추천 생성 → 저장 → 진행 상태 업데이트 순으로 동작합니다. (슬라이드: sequence_diagram_practice)

## 7) 결론/향후 (20초)
- 공학 원리 적용은 품질·확장성·사용자 가치 모두에 긍정적이었다는 점을 확인했습니다.
- 다음 단계로 라우트 분리 심화, 자동화 테스트/보안 강화, 성능/캐싱, API 문서화, Docker/배포 파이프라인을 계획하고 있습니다.

## 8) 마무리 (10초)
- 경청해 주셔서 감사합니다. 질문 받겠습니다.
